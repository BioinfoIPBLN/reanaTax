## v1.0.0dev - [unreleased]

Initial release of BioinfoIPBLN/reanatax, created with the [nf-core](https://nf-co.re/) template.

### `Changed`

- The taxonomy verdicts of the Kraken2 route - `--drop_host_clade`, `--drop_non_microbial`, `--drop_host_taxon` - now also apply to the KrakenUniq, PathSeq and Metax cohort tables (`taxonomy_drop`; `merge_pathseq.py` and `metax_merge.py` gain `--drop-list`), so the classifiers are compared on the same footing. The lists name the taxa Kraken2 saw.

- The end-of-run cleanup stops the Kraken2 daemon only if it started after the run began; one already running belongs to another run on the node, or was left by an earlier one, and is left alone with a warning. Under `-profile slurm` the run warns that the cleanup, which runs on the submit host, cannot reach the daemons on the compute nodes.

- Kraken2 is 2.17.2 (was 2.1.6), in both `KRAKEN2_KRAKEN2` and `KRAKEN2_DAEMON`. Every read gets the same call as before: the per-read output was identical on three CLID libraries, 2.23 M reads against core_nt, and so was the speed. Two things in the report change.
  - **Minimizer counts.** Column 4 (minimizers observed) now counts hits that 2.1 undercounted: 1.5 to 5 times as many, 3 on the median.
  - **Domain rank.** Domains are ranked `D`, not `R2`.

  The minimizer filter's duplication ratio is built on that column, so `--minimizer_max_duplication` is now unset by default and resolves to 300 for Kraken2 and 100 for KrakenUniq, whose counts did not change. On 70 PRISM CLID runs classified with both versions, 300 reproduced 2.1.6's decisions at 100:
  - **Per run:** all but 48 of 13,118 calls agreed, and none of the 48 is a known infection. Keeping 100 would have dropped 297 more.
  - **Pooled, as the pipeline runs the filter:** all 1,779 calls agreed.

  The container is rebuilt from bioconda through Seqera's community service, with `gzip`, `bzip2` and `util-linux` added, because the service's new minimal base lacks them. Without `gzip`, the `kraken2` wrapper classifies no reads from compressed input and still exits 0; without `flock`, the daemon cannot queue its clients. The PRISM module keeps `kraken2=2.1.3`, PRISM's own pin. Kraken2 tasks recompute once on this version.

- fastp trims homopolymer tails by default (`--trim_poly_x`, a new parameter, `true`; not applied under `--single_cell`, whose barcode read can end in poly-T next to the UMI). Libraries that read into the 3' end (Visium, 10x and Drop-seq cDNA reads, 3' mRNA-seq) carry poly(A) on many reads. Under `--very-sensitive --no-softclip`, HISAT2 placed those reads on genomic poly(A) tracts, absorbing the rest of the read as insertions, and its `-k 50` search through such tracts made alignment slow. On the Visium deposit PRJNA912890, up to 99.8% of read 1 in a library was 55 bp of other sequence and 95 bp of poly(A): 80% of those reads aligned that way, and trimming made alignment 23 times faster (137 s against 6 s per 100,000 pairs; chunks had taken up to 15 h). Trimming changes fastp's arguments, so resumed runs recompute from trimming once.

- `--hisat2_args` defaults to `--bowtie2-dp 2 --score-min L,0,-1 --no-softclip -k 5` (was `--very-sensitive`): the preset's scoring, without soft-clipping, and 5 alignments sought instead of 50. `--very-sensitive` sets `--score-min L,0,-1`, and HISAT2 charges 1 point per soft-clipped base at Illumina qualities, so a read that matched the host over 9-25 bp and clipped the rest counted as host. On PRISM's WGS negative controls that removed 14-39% of the reads, almost none of them human. On 70 low-count CLID runs the known infection is now found in 36 instead of 26, none lost, at five times the human reads reaching Kraken2 (removed there by `--drop_host_taxon`). `-k 5` because host depletion uses one alignment: on ordinary libraries it was 1.25-1.5 times faster than `-k 50` and removed the same reads to within 0.004%. `--hisat2_max_alignments` now works with the default. RNA runs recompute their host alignment once.

- With `--hisat2_chunk_size`, the library is now cut into chunk files in one streaming pass (`HISAT2_CHUNKSPLIT`, which replaces `HISAT2_CHUNKPLAN`), and each chunk task aligns one file. The chunks used to be offsets into the whole FASTQ (`-s/--skip`, `-u/--upto`), so every chunk decompressed and parsed the library up to its own window and the reading grew with the square of the chunk count: on PRJNA912889, four libraries of ~540 M pairs at 27 chunks each, a library's chunks 20-26 averaged 3 h 26 m against 2 h 23 m for chunks 1-5. The cut costs a second copy of the library on disk until the sample's chunks are merged, and `--cleanup_intermediates` deletes it then, alongside the chunk BAMs. Chunks are now numbered with four digits (`part0001`). Chunked runs recompute their host alignment once on this version.

- Chunk alignment tasks take an equal share of `--resource_limit_cpus` instead of a fixed 12 cores: as many side by side as fit at about 16 each, so 32 runs 2 x 16, 64 runs 4 x 16 and 40 runs 3 x 13 (16 when the limit is unset). Under 32, the fixed 12 fitted two chunks and left a quarter of the cores idle for the whole alignment.

- With `--save_host_bam false`, the default aligner (`HISAT2_ALIGN_SPLIT`, under `--require_both_mates_unmapped`) no longer writes a host BAM. It used to compress the whole alignment stream into a temporary BAM on one core and read it back twice, once for the host BAM and once for the non-host FASTQs, and a chunked run then merged the chunk BAMs, all for a file the run discarded. HISAT2's output now goes through `-f 12` straight into `samtools fastq`, which selects the same reads. The vendored nf-core `HISAT2_ALIGN` (`--require_both_mates_unmapped false`) still writes its BAM. The module takes a new input, so these alignments also recompute once.

- Samples now move through the pipeline one at a time instead of in cohort-wide steps. Two `groupTuple` calls without an expected size held every sample back until the whole cohort had reached the same point: the run grouping after download, so trimming waited for the slowest download, and the chunk merge after host alignment, so no merge, second host pass or Kraken2 run could start until every chunk of every sample had aligned. Both now carry the expected count with `groupKey`: runs per sample from the run sheet, and chunks per sample from the chunk files. So a sample is merged, depleted and classified while others are still downloading or aligning. Kraken2 still classifies one sample at a time, since the daemon takes one client, but it starts early. Incomplete groups are still emitted at the end (`remainder: true`). Task inputs are unchanged, so existing caches still resume.

### `Fixed`

- **The `_frac` columns of a filtered Bracken table depended on which filter last removed a taxon.** A filter that dropped something rescaled the fractions to sum to 1 over the rows in front of it, and one that dropped nothing left them alone. So the PRISM and gene-diversity passes, which run on the already-thresholded table, scaled every fraction up by the mass the abundance thresholds had removed, but only when their own drop list matched something. Likewise, cells zeroed by the negative-control filter left the denominator only if some drop list matched. The denominator is now read back from the table and carried: drop lists and control zeroing remove their reads from it, and the abundance thresholds never do (`fraction_state()`/`rescale_fractions()` in `bin/filter_abundance.py`, also used by `bin/control_filter.py`). docs/output.md says what `_frac` means.

- **`filter_abundance.py` skipped a `--drop-taxids` file that did not exist** and filtered nothing; it now stops and names the path.

- **`--minimizer_distinct_scale` counted reads more than once.** Library depth was the sum of clade reads over every rank beginning with S, which counted a species again in each of its strain rows (S1, S2) and, in KrakenUniq reports, also counted superkingdom and species group, raising the scaled threshold accordingly. Depth is now the root's clade count, the classified reads the help text always described. The option is off by default.

- **`host_microbe_correlation.py`'s docstring said it read combine_kreports tables**; it never did, and now refuses one by name. Its taxon-name row keys cannot collide on the Bracken table it is given, because Bracken's own combiner stops on a name shared by two taxids.

From an independent code audit of 3f8bc51, each finding checked against the code first:

- **HUMAnN profiled samples against other samples' taxa.** Reads and taxonomic profiles reached `HUMANN3_HUMANN` as two queue channels, paired by arrival order. A library in which Kraken2 classified nothing has no Bracken report, so from that library on, every sample was profiled against the next sample's taxa. They are now joined on the sample id, and a library without a profile is left out with a warning.

- **`--target_taxid` extracted nothing.** Its join of the non-host reads with Kraken2's per-read output was keyed on the whole meta map, and the taxonomy step adds `bracken_r` to its meta, so the two never matched. It now joins on the sample id.

- **The target's gene DE stopped.** `merge_featurecounts.py` left the `.target` label on the targeted taxon's count columns, so no sample matched `--da_metadata`.

- **`--target_transcripts` was refused without `--target_reference`**, although it needs no genome. It is now accepted on its own (with a warning when both are given), and the warnings about `--target_gtf` no longer fire on the kallisto route.

- **`--host_microbe_correlation` was refused with `--host_transcripts`** and only accepted `--quantify_host`.
  - **Without host DE:** it now runs with either host-count route, and without host DE when `--host_de_method` is unset.
  - **Without Bracken:** it is refused with `--skip_bracken` or `--skip_kraken2`, where it used to be skipped without a word.
  - **Host DE with `--skip_kraken2`:** this no longer refers to the outputs of a Kraken2 subworkflow that never ran.

- **PRISM could not see its databases** under `--prism_container`. They are passed as paths rather than staged, so nothing mounted them; they are now bound read-only.

- **Bracken failed on an archived database** under `--bracken_read_length auto`. A `.tar.gz` database cannot be listed before it is unpacked, so the measured read length (143, say) reached `bracken -r`, and no database ships that distribution. The length is now snapped after UNTAR, before classification.

- **The UniVec pass got the wrong alignment settings** under `--hisat2_chunk_size`. Its chunks took the host chunk rule, which applies `--hisat2_args` - the `--score-min L,0,-1` the UniVec rule exists to keep away from a plasmid backbone - and a `.host` read group.

- **exploreMetaTax:**
  - **Uploads:** the upload path merged HUMAnN tables with a `Reduce(merge)` fold that re-sorts the whole key on every step; it now uses `join_humann_wide()`, as the dataset path does.
  - **Docs:** its README, and docs/output.md, told users to upload `--outdir` directly, whose file names the app skips or misreads; they now point to the `--exploremetatax_bundle` archive.

- **The bundle labelled every regrouped HUMAnN table as KEGG orthologs.** It now follows `--humann_regroup`: reactions for `*_rxn`, left out for groupings the app has no slot for.

- **The `sc_kmer_denoise.py` MultiQC section said "BH-adjusted"** when the default correction is Holm; it now names the correction used.

- **The `--skip_kraken2` warning that nothing classifies the reads** ignored PathSeq and PRISM.

- A run stopped when one library had classified reads but no taxon at `--bracken_level` with `--bracken_threshold` of them. Bracken exits 1 with "no reads found" on such a report, and that is what a blank looks like: on PRISM's WGS negative controls, SRR28772246 had 226 classified reads with no species above 4, and the run died ten minutes in. These libraries are now left out of Bracken and the Bracken tables with a warning, as all-unclassified ones already were, and stay in the Kraken2 tables.

- The minimizer filter removed real organisms that were sequenced deeply. Its duplication limit was flat at 100, and a small genome runs out of distinct minimizers long before it runs out of reads, so its observed/distinct ratio climbs with depth: on PRISM's CLID benchmark it condemned RSV at 1,008,307 reads (duplication 161) and rubella at 15,276 (196), each the top species of its run. The limit now rises with coverage, to `--minimizer_max_duplication` x coverage / `--minimizer_duplication_coverage` (0.01), for a taxon with at least `--minimizer_duplication_min_distinct` (1000) distinct minimizers. The floor is what keeps barcode-only database entries, fully covered by a few hundred minimizers, from riding the raised limit; across the benchmark runs so far 1 of the 529 taxa the flat limit condemned clears both bars (squirrel monkey retrovirus, a real cell-line passenger), and so do both real infections. The evidence table gains a `duplication_limit` column.

- The minimizer filter only looked for `inspect.txt` in the Kraken2 database directory, so a database that keeps it gzipped got no coverage denominator, and a run could fail at its last cohort step: the lookup happens at launch and the file is read at the end, and when the shared FGCZ databases were switched to `inspect.txt.gz` partway through a run (2026-10-08), `ABUNDANCE_MINIMIZER` died with `FileNotFoundError: inspect.txt` after every sample had been classified. `inspect.txt.gz` is now accepted too, and `minimizer_filter.py` reads either, telling them apart by the gzip magic.

- With `--hisat2_chunk_size`, every chunk's BAM and unmapped FASTQs were copied into `hisat2/`, and a run could abort with `Failed to publish file: .../<id>.part001.bam ... NoSuchFileException`. The chunk tasks and `HISAT2_CHUNKPLAN` were meant to publish nothing, but `publishDir = []` sets nothing, so the generic rule stayed in force: 289 GB of chunk files in one PRISM CLID batch's results. Since samples stream through host depletion, a small sample's merge can finish, and delete its chunk BAM, before the publisher has copied it. That aborted a 135-sample batch after 12 hours, and because `--cleanup_intermediates` had already removed the downloads, the resume started over. Both now use `enabled: false`.

- Every MultiQC run left 20-50 `/tmp/fileXXXXXX.html` files on the node under Singularity/Apptainer, about 14,000 on one node after a month of benchmarks. `export_plots` renders each plot through Kaleido, which names its HTML scaffolds with `tmpnam()`, a call that always uses `/tmp` and ignores `TMPDIR`, and never deletes them. Inside these containers `/tmp` is the host's. MultiQC now gets a private `/tmp`: a directory of its own under the node's `TMPDIR` (`/tmp` when unset), removed when the task ends. Docker already gave each container its own `/tmp`.

- A transient ENA error could become a run accession. The ENA portal sometimes answers a metadata query with its error message as the data line ("ERROR occurred. Not all results may have been written.Query: ..."). `fastq-dl` wrote it into the run-info table, `runinfo_to_runsheet.py` passed it on as a run, and FASTQDL then failed on an accession that does not exist. It hit 6 of 180 experiments in one CSI-Microbes plate download. The script now fails on any run accession that is not `SRR`/`ERR`/`DRR` plus digits, so `FASTQDL_METADATA` retries the query, which succeeds. It fails rather than skips because the message says the results may be incomplete.

- `--bracken_threshold` defaulted to `0`, where Bracken's own default is `10`. Below the threshold Bracken drops a taxon; at or above it, the taxon also receives a share of every read Kraken2 could only place higher in the tree. At `0`, a species with one or two Kraken2 reads qualified, and on host-dominated libraries the reads being shared out are mostly leftover host: on GSE207405, 72% of the species counts were redistributed reads, SARS-CoV-2 went from 10 Kraken2 read pairs to 4,427 and _E. coli_ from 4 to 9,564. It now has no default and is required whenever Bracken runs, because neither value suits all data: 10 (Bracken's own default) for host-dominated or low-biomass libraries, 0 when a taxon with a handful of reads must stay in the tables, such as shallow blanks under `--negative_controls`. "Choosing `--bracken_threshold`" in `docs/usage.md` explains the choice, and the error names both options. The test profiles pass 0.

- ALDEx2 reported the fold change with the wrong sign whenever a contrast had no covariates and the sample group sorted alphabetically before the reference, as KO does before WT. That branch handed `aldex.clr` the groups as a character vector, and `aldex.effect` reports `diff.btw` as the second level minus the first in `as.factor()` order, not in the reference-first order the script sets up. On GSE302342 a taxon found only in WT_MCAO was reported as higher in KO_MCAO. The sign is now oriented explicitly. The covariate branch (`aldex.glm`) and ANCOM-BC2 were already correct.

- `--host_microbe_correlation` never ran. The subworkflow joined the host count matrix (`[id: 'reanatax']`) with the Bracken table (`[id: 'bracken_combined', ...]`) on their metas, and `join` drops an unmatched key without a word, so the process always received nothing. Now `combine`, since both sides are single cohort-level tables.

- Differential abundance and the host-microbe correlation tested the host. They read the raw combined Bracken table, which is deliberate for the abundance thresholds - the methods apply their own - but meant `--drop_host_taxon`, the host clade and every evidence-filter verdict never reached them: on GSE302342, _Mus musculus_ and _Mus caroli_ were among the ~12 taxa tested. They now read `bracken_combined_<level>.verdicts.filtered.tsv`, the same filter with every drop applied and every threshold at zero.

- `read_accounting` overstated the non-host fraction under `--require_both_mates_unmapped`, ~30x on GSE302342 (1.24% of raw reads against 0.04% actually released). It took `nonhost_reads` from HISAT2's "aligned concordantly 0 times", which counts every pair that failed to align as a pair, including pairs with one host mate; the split route releases only pairs where neither mate aligned, a number the summary never prints. When a Kraken2 report exists, `nonhost_reads` is now what Kraken2 received and `host_removed_reads` the rest of what entered host depletion, which is exact on either route. `classified_pct` and `host_carryover_pct` follow.

- Runs could abort with `Unexpected error while finalizing task 'HISAT2_MERGECHUNKS (...)' - cause: null`, a `java.util.ConcurrentModificationException`. The subworkflows that put mate 1 first did it with Groovy's `List.sort`, which sorts in place, on the list object the task itself had emitted. Nextflow binds a task's outputs to its channels before it publishes them, so the publisher could still be iterating that list while the operator reordered it. Now `toSorted`, which sorts a copy: after host depletion, after the download and after SortMeRNA.

- `HISAT2_MERGECHUNKS` and `CLEANUP_INTERMEDIATES` missed the cache on every `-resume`, and so did everything downstream of the merge: sorting, QualiMap, featureCounts, Kraken2, Bracken. Both scripts named `${workflow.workDir}` in their cleanup guard. Nextflow hashes every variable a script mentions, even in a branch that does not run, and it hashes a Path by its size and modification time. Those change whenever a run creates task folders. On GSE207405, each of three DA-only reruns redid 185 tasks. The work directory is now passed as a String input, which is hashed by value, and it is resolved with `readlink -f` before the comparison, so a work path that goes through a symlink no longer makes the guard skip every file.

- Downloads of deep libraries could not finish. FASTQDL had 8 hours per attempt, and on GSE145926 a ~110 GB 10x library needed longer: ENA hands out connections that run anywhere from ~0 to ~18 MB/s, and fastq-dl restarts a file from zero on retry, so a killed transfer near the end was a total loss. Now 16 hours per attempt, still scaling with the attempt number. The download step also gets 8 cores instead of 2 - they only matter on the SRA fallback, where fasterq-dump and pigz use them, and two-thread pigz had spent ~6 h on one 410 GB R2 - while the metadata query stays at 1. Not 12: the cores are held for the whole download, mostly network waiting, and four parallel downloads at 12 would reserve three quarters of a 64-core budget.

- `--drop_host_taxon` never reached the single-cell matrix. It was an `ext.args` on the abundance filter, so it removed the host from the combined tables and left it in `cell_taxa` -- the one removal in the pipeline that let the two views disagree, against the invariant the rest of the single-cell branch is built on. It showed up as two spurious "significant" Homo sapiens cell-type enrichment results on the CSI-Microbes plate. It now travels on the same shared drop list as every other verdict, so both views agree. Ordering is unchanged where it matters: the matrix is filtered after `--sc_kmer_denoise` and `--sc_ambient`, both of which still see the host rows they need.

- `--single_cell` aligned only the FIRST library of a cohort. `PREPARE_HOST_REFERENCE` emits its STAR index as a queue channel holding one item, and a process pairs a queue channel element-by-element against the reads, so `STARSOLO` ran once and every other library was dropped with no error -- the log said `STARSOLO | 1 of 1` for a three-library run. The bulk route already guards this at every `HISAT2_ALIGN*` call site; this one did not, and had only ever been exercised one sample at a time. Also filtered the null-read tuples that `join(..., remainder: true)` admits, which is how the loss surfaced: as `Path value cannot be null` inside Kraken2, on a process whose own error message then failed to render and reported `No such variable: task` instead.

- `STARSOLO` could not run at all: it forced `--outSAMtype BAM Unsorted` while asking for CB/UB in `--outSAMattributes`, and STAR refuses that combination because the corrected barcode and deduplicated UMI are only known once the solo pass has finished, which it does during the sort. Now `SortedByCoordinate`, with `--limitBAMsortRAM` derived from `task.memory` rather than left at STAR's default of 0 ("the genome index size", ~30 GB for human, on top of the ~30 GB the index already occupies).

- `SCTAXA_FILTER` published every library's filtered matrix under one name. `ext.prefix` was the constant `'reanatax.filtered'`, which is correct on the plate route where `SCTAXA_PLATE` builds a single cohort matrix, but on the droplet route the matrix is per-sample: three tasks wrote `reanatax.filtered.cell_taxa.tsv` into the same publish directory and the last to finish overwrote the rest. Two thirds of the cohort vanished behind a `3 of 3` tick. Now derived from `meta.id`, which leaves the plate filename byte-identical.

- A `--kraken2_db` given as a `.tar.gz` produced a queue channel holding one item, which a process pairs element-by-element against the reads: the cohort would classify its first sample and silently stop. Unpacked-directory databases were unaffected, which is why every benchmark run was correct and the two-sample `test` profile never asserted on it. Now `.first()`, so the database is a value channel available to every task.

### `Added`

- `--build_databases` (with `--db_input`): builds the classifiers' databases from your own genomes, as a run of its own instead of an analysis (`workflows/build_databases.nf`). A CSV gives one genome per row - an id, its NCBI taxid, and a FASTA or an assembly accession fetched with ncbi-genome-download.
  - **Headers:** every header is rewritten to carry the taxid (`kraken:taxid|<n>`), so no accession-to-taxid table is needed.
  - **Taxonomy check:** every taxid is checked against the NCBI taxonomy (`--db_taxonomy`, or the taxdump fetched for the run) before anything is built.
  - **Builds:** `kraken2` (with Kraken2 2.17.2, the version the analysis runs, and `inspect.txt` for the minimizer filter's coverage), `bracken` (one distribution per `--db_bracken_read_lengths`, default 50,75,100,150), `krakenuniq` and `sylph` (with a sylph-tax lineage table).
  - **Output:** everything lands in `<outdir>/databases/` in the layout `--kraken2_db`, `--krakenuniq_db`, `--sylph_db` and `--sylph_taxonomy` read.
  - **Container:** Kraken2 and Bracken build in a new image (`kraken2_bracken_coreutils_findutils_pruned`). The classification image lacks `find` and `xargs`, which `build_kraken2_db.sh` calls, and Bracken's own image carries Kraken2 2.1.3.
  - **Not built here:** MetaPhlAn/HUMAnN, PathSeq and Metax databases; docs/usage.md says where they come from.

- `--build_databases metaphlan`: a standalone MetaPhlAn 4.2 database from the genome sheet, its markers chosen as MetaPhlAn 4's were (Blanco-Míguez et al., Nat Biotechnol 2023) and as HROM reimplemented the recipe. The steps:
  - **Genes:** from a new optional `cds` column, NCBI's CDS file for an annotated accession, or pyrodigal, which picks code 4 when it codes markedly more.
  - **Core families:** MMseqs2 families at 90% identity and 80% coverage, kept when core to a species at MetaPhlAn's coreness threshold.
  - **Uniqueness:** 150-nt fragments are mapped with Bowtie2 against every species' genomes and the optional `--db_metaphlan_screen` (host, vector).
  - **Selection:** up to 200 markers per species; a species with fewer than 10 is left out.

  The database is written as `<db_name>.pkl`, `<db_name>.fna` and a large Bowtie2 index (`bin/mpa_genes.py`, `mpa_candidates.py`, `mpa_uniqueness.py`, `mpa_select.py`; `db_lineage.py --mpa-output`).
  - **Eukaryotes** without coding sequences stop the run before gene calling.
  - **Viruses** are left out of the MetaPhlAn database only.
  - **Sheet ids** can no longer contain `__`.
  - **`--db_name`** can no longer contain `.`, which MetaPhlAn reads as the end of an index name.

- `--long_reads ont|pacbio`: a route for Oxford Nanopore and PacBio libraries, one FASTQ per sample and one platform per run.
  - **Trimming:** fastplong (`FASTPLONG`, `--fastplong_args`, default `--length_required 200 --mean_qual 10`) in place of fastp, with `--trim_poly_x`, `--trim_low_complexity` and `--adapter_fasta` applied as before.
  - **Host depletion:** minimap2, as Hostile does it for long reads (`MINIMAP2_INDEX`, `MINIMAP2_ALIGN_SPLIT`). The preset is `splice` or `splice:hq` for RNA and libraries of unknown kind, and `map-ont` or `map-hifi` for DNA, unless `--minimap2_preset` sets one for every library. One index is built per preset in use, since k-mer and window size are fixed in it. A read is host when its primary alignment maps. The summary is written in Bowtie2's format, so read accounting and MultiQC read it unchanged. `--host_aligner` gains `minimap2`.
  - **Classification:** Kraken2, KrakenUniq and sylph. `--skip_bracken` is required, since no Bracken distribution describes reads of thousands of bases.
  - **MetaPhlAn** in its long-read mode. MetaPhlAn builds its minimap2 index inside `--db_dir` on first use, which parallel samples would race on and a read-only database refuses, and it only adopts an existing index over 30 GB. So the index is built once per run (`METAPHLAN_MM2INDEX`, `--metaphlan_minimap2_ps`, MetaPhlAn's default presets), each sample is mapped with MetaPhlAn's own command, and MetaPhlAn profiles the alignments (`--input_type sam --long_reads --nbases`). `--metaphlan_mm2_index` reuses an index published under `reference/metaphlan/`. `METAPHLAN_PROFILE` takes two new inputs, so short-read MetaPhlAn tasks recompute once.
  - **Refused up front:** the single-cell routes, `--read2_only`, `--remove_rrna`, `--univec`, `--assembly`, `--run_prism`, PathSeq, `--run_metax`, `--run_humann`, kallisto, `--target_taxid` and `--run_polya_check`.
  - **Archive runs** carry their instrument platform (`meta.platform`): an ONT or PacBio run without `--long_reads`, or of the other platform, stops the run, and runs of different platforms are not merged.
  - `--quantify_host` counts long reads with featureCounts' `-L`.

- `--host_mask` (with `--host_mask_kmer_length`, default 150, and `--host_mask_kmer_step`, default 10): Hostile's masking (Constantinides et al., Bioinformatics 2023). The genomes given are cut into k-mers, aligned to each host reference with minimap2, and every host region they reach is replaced with N before any index is built, so reads of those organisms survive depletion (`bin/host_mask_kmers.py`, `HOST_MASK`). Every host pass is masked. Prebuilt indexes are refused, since masking acts on the FASTA. The masked regions and a summary are published under `reference/mask/`.

- Prebuilt indexes may be plain `.tar` archives as well as `.tar.gz`/`.tgz`, in `--host`, `--hisat2_index`, `--bowtie2_index`, `--star_index` and `--target_reference`. This is the form Hostile distributes its Bowtie2 indexes in, masked or not.

- `--sc_host_de_pseudobulk` (with `--sc_host_de_min_donors`, default 3): the infected-vs-bystander host response tested across donors as well as within each library. `--sc_host_de` tests each library with its cells as the units, which says nothing about the cohort (Squair et al., Nat Commun 2021). Each library's infected and bystander cells are now also summed per taxon x cell type, and the sums are tested with DESeq2/edgeR, `~ donor + state` (`bin/sc_pseudobulk.py`, `SCTAXA_PSEUDOBULK`). A group too thin for the expression filter is listed and skipped, not failed.

- `--virus_min_rel_abundance` (unset by default): a separate relative-abundance floor for viruses, the descendants of 10239 in the run's reports (`VIRUS_EXPAND`). A virus genome draws a far smaller share of the reads than a bacterium at the same load. On the benchmarks (benchmark/filters_8x):
  - **The cost of one floor:** the 0.1% cohort floor removed wastewater _Mamastrovirus_ from all 35 libraries carrying it; exempting viruses (`0`) kept them.
  - **The cost of exempting:** viral specificity on PRISM's CLID (RNA viruses 60.9% to 49.1%), with bacteria and fungi unchanged.
  - **Ma et al.'s RNA-virus rule:** the per-kingdom scheme of Ma et al. (J Mol Diagn 2026) was benchmarked too and is not offered. Its rule, z > 3 against the other samples, removed SARS-CoV-2 from all nine infected BAL libraries. Their z-score rule for negative controls matched the ratio rule's specificity on the CSI-Microbes plate and the PRISM blanks while leaving more background, so `--control_statistic` is unchanged.

- Reads per million of the whole library: `kraken2/kraken2_combined_report.filtered.rpm_total.tsv` and `bracken/bracken_combined_<level>.filtered.rpm_total.tsv` restate the filtered tables against each sample's trimmed read total from the read accounting (`bin/rpm_total.py`). Every other fraction is a share of what was classified and kept, which in host RNA-seq hides the scale.

- A warning, once per run, when trimmed reads average 60 bp or less, naming the samples: Kraken2's 35-mers are few per read at that length, sylph loses most of its sensitivity (Ma et al., J Mol Diagn 2026), and MetaPhlAn discards reads under 70 bp by default (`--read_min_len`).

- Unit tests for the Python helpers in `bin/` (`tests/bin/`, pytest, standard library only), run by a new `bin-tests` GitHub Actions job.

- `--read2_only` (off by default): drops read 1 of each pair before trimming and takes the library on as single-end read 2, for barcode-read libraries (Visium, BD Rhapsody, 10x, Drop-seq) run without `--single_cell`. Their read 1 is barcode + UMI (+ poly-T). It cannot align to the host, and in classification it adds k-mers that are not transcript: on a BD Rhapsody deposit 13.6% of microbial assignments owed it to read 1 alone, and phage phi29 entirely. An internal poly-T also made HISAT2 slow on it, 246 against about 20 min per chunk. The cleanup of downloaded reads now joins on the sample id, since the layout changes in between.

- `--drop_non_microbial` (off by default): drops every taxon under Metazoa, Viridiplantae, other sequences and unclassified sequences from the final tables, read from the run's own Kraken2 reports (`NONMICROBIAL_EXPAND`, `bin/non_microbial.py`). Host reads that escape depletion land on animals and plants outside the host's own clade, which `--drop_host_clade` cannot reach: on a mouse stroke single-cell cohort, 590 non-microbial calls per library against 65 microbial, 219 after `--drop_host_clade phylum`. Opt-in because helminths, a blood meal or a xenograft's mouse cells are animals too.

- `--host_aligner` (`auto` by default): host depletion aligns DNA libraries with Bowtie2 and RNA with HISAT2. HISAT2 is splice-aware and was aligning every library, so genomic reads could be split across introns that do not exist, and there was no local mode. Under `auto` a library's kind comes from the archive's library strategy, or its source when the strategy is OTHER (accessions), or a new optional samplesheet column `molecule`; unknown libraries go to HISAT2. `--bowtie2_args` (default `--very-sensitive`, local presets allowed) and `--bowtie2_index` (prebuilt, one per host reference) go with it. Unset, the Bowtie2 index is built from the host FASTA, or from a prebuilt HISAT2 index with `hisat2-inspect`, and each aligner's index is built only when some library needs it. Chunking, the both-mates-unmapped split, multi-reference passes, read accounting and MultiQC cover both. Bowtie2 summaries are `<sample>.<label>.bowtie2.summary.log`.

- `--run_taxpasta`: the per-sample outputs of Kraken2, Bracken, KrakenUniq and MetaPhlAn, standardised by [Taxpasta](https://taxpasta.readthedocs.io) into one table per profiler in one shape - taxonomy_id plus a count column per sample - so profilers can be compared on the same library without a parser for each. Built from the raw per-sample outputs, before this pipeline's evidence filters. sylph, Metax and PathSeq are not read by Taxpasta 0.7 and keep their own cohort tables. MetaPhlAn profiles written with the default `-t rel_ab_w_read_stats` are trimmed to the four-column layout Taxpasta insists on, keeping the three columns it reads. Sample names come from a samplesheet, not from file names, and a single-sample run is written with `taxpasta standardise`, since `merge` needs two. `--taxpasta_taxonomy_dir` adds names, ranks and lineages, and the pipeline refuses `--add-name` and friends without it.

- `--krakenuniq_db` accepts a `.tar.gz`, unpacked first as on the Kraken2 route.

- Test profiles `test_krakenuniq` and `test_sylph`, with nf-test files. `test_krakenuniq` is a positive test: nf-core's SARS-CoV-2 KrakenUniq database against the SARS-CoV-2 test reads, with Taxpasta over Kraken2, Bracken and KrakenUniq. `test_sylph` runs the sylph-only fast path (`--run_sylph --skip_kraken2 --skip_host_removal`) against nf-core/taxprofiler's sylph test database, which holds no SARS-CoV-2 - so the empty result is the thing tested. No snapshots yet; the tests assert success and the key outputs, and the first run records the rest. Metax and MetaPhlAn have no profile: Metax has no test database or public container, and MetaPhlAn's only small test database sits under a `delete_me/` path in nf-core/test-datasets.

- `--run_metax`: species-level profiling with [Metax](https://github.com/hzi-bifo/Metax), which aligns reads to a genome collection and keeps a taxon only when its reads cover the genome the way random sampling at that depth would (observed over expected breadth, OEBR, at genome and chunk level). A taxon whose reads pile onto one region - a contaminated reference contig, a kitome fragment, a conserved gene shared with the organism really present - is dropped, which is what the host-k-mer and minimizer filters approach indirectly. It reports NCBI taxids, so its calls line up with Kraken2's without a name mapping. Additive like `--run_sylph`, and with `--skip_kraken2` it replaces Kraken2 under the same restrictions. `--metax_db` takes a database's `metax_db.json` or its directory, `--metax_dmp_dir` a taxonomy dump, and output lands in `metax/`, with cohort tables keyed on taxid in which an empty sample stays a column of zeros. There is no public container - Metax is on its author's conda channel, not bioconda, and that package ships `metax` without the `maCMD` aligner - so the module carries a conda environment for both, `-profile wave` can build from it, `--metax_container` takes an image, and the pipeline warns at startup when none of these will apply. Not yet run on this pipeline's data; its authors note that coverage-based filtering can drop true taxa in RNA-derived data.

- `--run_sylph`: species-level profiling with [sylph](https://github.com/bluenote-1577/sylph), which calls a genome from its containment ANI (95% or above) instead of classifying reads, and in exchange makes far fewer false positives than per-read classification, at a fraction of Kraken2's memory. Additive like `--run_metaphlan`: alongside Kraken2 it puts a whole-genome call next to a per-read one on the same library; with `--skip_kraken2` it replaces Kraken2 and carries every restriction that flag already does, because sylph assigns no reads for the single-cell, host-k-mer or minimizer logic to use. Adding `--skip_host_removal` skips alignment too - sylph needs no host depletion, since a genome that is not in its database cannot be called. `--sylph_db` takes one or more `.syldb`/`.syl2db` databases (sylph 1.0.0, so the two-stage GTDB r232 format works), `--sylph_taxonomy` the matching sylph-tax tables, and the output lands in `sylph/`, where a sample with nothing detected stays a column of zeros. Local modules rather than the nf-core ones, which pin sylph 0.9.0. Not yet run on this pipeline's data: sylph's model assumes reads that sample the whole genome and its documented floor is 0.01-0.05x coverage, so on transcriptomes, and 3' single-cell libraries above all, a missing call is weak evidence of absence.

- `--drop_host_clade genus|family|order|class|phylum`: drop every taxon under the host's own clade, not just the host taxid. A host read that misses the host genome is assigned to the nearest relative the database holds, so the leakage arrives wearing a sibling's name. Measured on the CSI-Microbes 10x cohort with Homo sapiens already dropped, Pan/Pongo/Gorilla/Macaca/Tupaia were still 84% of everything called microbial in the uninfected library: 0.1% at genus (most databases hold one species per host genus, so that rank is nearly useless), 58-66% at family, 71-88% at class. The lineage is read from the run's own Kraken2 reports, so the ranks match the database and there is no external taxonomy to maintain. It travels on the shared drop list rather than on FILTER_*'s --drop-taxid, so unlike --drop_host_taxon it also reaches the single-cell matrix, where Homo sapiens rows had been outliving it. Off by default and warned at class and above: dropping the host's class is free on human tissue and deletes the mouse on a xenograft. It is a prediction from the taxonomy and not a measurement of the reads, so leakage landing outside the clade -- the same cohort carries turbot, spruce and Naegleria -- still needs --host_kmer_filter.

- `--assembly`: de novo assembly of the non-host fraction, and a verdict on every taxon from the contigs. The five existing filters all score a taxon by counting things about its reads; none of them ever produces a longer sequence, and reads placed by index hopping or piled on one conserved locus do not assemble. MEGAHIT by default rather than an RNA assembler even though the input is usually RNA-seq -- what survives host depletion is overwhelmingly bacterial and archaeal, with no isoform structure to model, and what RNA-seq does impose is coverage skew, which is what a multi-k metagenome assembler is for; `--assembly_assembler metaspades` trades time and memory for contiguity. Libraries are POOLED first (`--assembly_pool group|all|sample`, defaulting to the contrast groups): per-library assembly is close to useless on the cohorts this is for, where a false positive sits at tens of reads per library. Contigs roll up the taxonomy from the contig report's own indentation, so a species-level contig supports the genus above it -- which is the rank where every false positive on the CSI-Microbes plate lived. Evidence only by default: `--contig_filter` is opt-in because a contig is strong positive evidence while its absence is weak negative evidence, and `--contig_min_reads` records rather than condemns a taxon too rare to have assembled.

- `--export_biom`: the classification as a BIOM table in `biom/`, off by default and read by nothing in this pipeline. The combined tables are already a taxa-by-sample matrix, which is why the differential-abundance step skips the `kraken-biom` round trip `EzAppDiffShot` does; this is for handing a run to QIIME 2, phyloseq or anything else that speaks BIOM. Built from the same per-sample reports Krona uses, then restricted to the taxids in the filtered combined report so it agrees with `*_filtered.tsv` instead of quietly reinstating everything the filters removed -- the pre-filter table is published as `*.unfiltered.biom` when the two differ. `--biom_metadata` (falling back to `--da_metadata`) is attached as sample metadata, and a sample missing from it stops the export by name rather than inside `pandas`. Two of kraken-biom's own behaviours are corrected on the way in: it names samples after the report FILE, so the reports are re-linked under their sample ids first; and it parses reports with a fixed six-field reader, so the two extra columns from `--kraken2_report_minimizer_data` are dropped rather than silently shifting rank, taxid and name. Ranks run domain to species rather than kraken-biom's default of order to species, because on the CSI-Microbes plate every false positive the control filter removed sat at genus.

- `--compression_level`, `--alignment_output_format` and `--cleanup_intermediates`: three independent answers to how much disk a reanalysis run holds. One 180-well cohort left 1.2 TB in `work/` -- 496 GB of alignments, 413 GB of FASTQ. The level reaches `samtools sort -l`, `samtools view -l`, `samtools fastq -c`, `fastp -z` (clamped to 1, which fastp requires) and the `pigz`/`gzip` calls in the local modules. `cram` roughly halves the sorted host alignments, indexes the reference once per pass rather than letting htslib rebuild it inside every task, and is refused up front alongside Qualimap and `--quantify_host` rather than failing per sample at the end of a run. `--cleanup_intermediates` deletes the per-chunk BAMs from inside the merge task once `samtools cat` has returned, and the downloaded FASTQs once trimming and raw FastQC have both read them -- ordering enforced by taking those tasks' outputs as inputs. Only paths inside the work directory are ever removed, so a samplesheet's own FASTQs are skipped and recorded rather than deleted; off by default, because a deleted intermediate cannot be resumed.
- `--negative_controls` / `--prevalence_filter`: the first filter here whose verdict is per LIBRARY rather than per taxon, and the only one that speaks to index hopping or well-to-well carryover. Those put genuine reads of a genuine organism into the wrong library -- nothing about the reads is wrong, so no evidence filter can see them, and the same taxon is then signal in one library and carryover in the next, which no single verdict per taxon can express. Measured on the CSI-Microbes plate, the distinct-minimizers-per-read ratio recommended by Kraken2's manual ranks those false positives ABOVE the true positives (AUC 0.415), and `--decontam`'s prevalence method must either delete the spiked organism or spare it entirely. A taxon is kept in a library only where it exceeds a stated multiple of its level in the controls, in counts per million classified reads; failing cells are zeroed and taxa failing everywhere leave as taxids. `--control_floor_reads` treats absence from the blanks as the bound it is rather than as zero, without which the test collapses to "any reads at all" for every taxon the controls missed. On the CSI-Microbes plate this is what turns the scorecard from 1 FAIL / 3 PASS into 0 FAIL / 4 PASS (specificity 88.2% -> 97.1%), at a cost of 4 of 62 detections. `sc_enrichment` is given the control list and leaves those libraries out of the test entirely: after the filter runs they are the only libraries still carrying their full background, so treating them as a cell type makes every reagent contaminant look hugely enriched in the blanks -- on that plate, 41 of 43 significant results, at log2fc 3.9 and adjusted p of 0. `--sc_apply_drop_list` carries the per-library verdicts into the cell-by-taxon matrix as well, taken from the combined kreport rather than from Bracken: the matrix holds whatever rank Kraken2 assigned, every false positive there sat at genus rather than species, and Bracken-derived verdicts reached none of them. `--prevalence_filter` is the no-controls fallback -- on that plate it removes six taxa holding 62.6% of all microbial reads, every one a known reagent contaminant, without touching the spike, and leaves the specificity failure exactly where it was, because the spiked organism is itself in 101 of the 180 libraries -- and is off by default because it is only sound where a universally present taxon cannot be real.
- `--sc_ambient`: how strongly each taxon is associated with cells rather than with the ambient pool, from STARsolo's raw and filtered matrices. Deliberately an annotation and not a filter: an empty droplet holds reagent contaminants, ambient soup, microbes from lysed cells AND genuine extracellular organisms from the tissue, so a taxon as common in the medium as in the cells is reported as `ambient_undecided` rather than as contamination -- only `--decontam`'s blanks settle that. `--sc_ambient_drop` will remove them, and is documented as correct only when the question is about intracellular microbes.
- `--prism_barcode_only`: drops the barcode read before PRISM sees the library, so Kraken2, STAR, minimap2 and BLAST all work on the cDNA read alone. Stricter than PRISM's own `--barcode_only`, which reaches only its BLAST step. Required with `--single_cell`, which is otherwise refused.
- `--univec`: UniVec depletion as a pass of its own, with its own alignment stringency. Not another `--host` entry, because `--very-sensitive` (`--score-min L,0,-1`) against a 3 kb plasmid backbone removes real reads; this pass runs end-to-end at HISAT2's own threshold and does not inherit `--hisat2_args`. Runs last, publishes the non-host FASTQs, appears in `read_accounting.tsv`, and works with `--skip_host_removal`.
- `--run_prism`: PRISM (sjdlabgroup/PRISM) wrapped as its authors wrote it -- candidate taxa confirmed by full-length BLAST against `nt`, GenBank annotation, host mapping and k-mer composition, scored by its XGBoost model over forty features. Takes the trimmed reads rather than the non-host ones, because several of its features are statistics of its own host removal. No public container exists, so `--prism_container` is required under docker/singularity and the module ships a conda environment for the alternative.
- `--shuffle_control`: a shuffled-read negative control. Every library is classified twice -- once as sequenced, once with each read shuffled so that its length, GC content and dinucleotide frequencies survive and none of its k-mers do -- and the ratio between the two is what the database produces from base composition alone. Three shuffles (`dinuc`, the Altschul-Erickson Euler-path shuffle, is the default), a fixed seed, an enforced detection floor when subsampling, and a second Kraken2 pass run with identical arguments to the first.
- `--gene_diversity_filter`: PRISM's `gene_div`, `prod_div`, `fprod`, `fugene` and `fuprod`, reproduced under PRISM's own names and definitions from HUMAnN's species-stratified gene-family table -- raw Shannon entropy as `vegan::diversity()` returns it, and shares of the across-taxa total rather than raw counts. A taxon's reads either spread across many gene families or pile onto one locus, and no read count can tell the difference. Runs a second time on the regrouped table when `--humann_regroup` is set, which separates "many gene families" from "many products". PRISM's score itself needs the other thirty-five features and is not reproduced; use `--run_prism` for that.
- `--pathseq_microbe_bwa_image`: GATK PathSeq as a third classification route, and the only one here that aligns rather than matching k-mers. Reports `unambiguous` reads separately from shared ones, and its results are kept in PathSeq's own units rather than converted into a Kraken report, so a disagreement between the routes stays visible.
- `--run_sparcc`: taxon co-occurrence inferred with SparCC (FastSpar). Refuses to start when the cohort cannot support the network -- fewer than ten samples, or a bootstrap p-value floor above what Benjamini-Hochberg needs for the number of pairs -- because an empty network from such a run means "this cohort cannot be asked" rather than "there are no associations".
- `--sc_host_de`: the host half of SAHMI. Host expression compared between cells carrying a taxon and bystander cells of the same type, by Wilcoxon rank-sum on log-normalised counts (Seurat's `FindMarkers` defaults). Requires cell-type annotations, because which cell types carry a taxon is itself a result and a pooled test would report the difference between cell types as a response to infection.
- `--sc_plate_based`: CSI-Microbes' plate-based route, for Smart-seq2 and relatives where every well is its own library. No barcode and no STARsolo -- each cell runs the bulk route and the cell-by-taxon matrix is those per-cell reports stacked -- and everything downstream of the matrix is shared with the droplet route.
- `--decontam_batch_column` and `--decontam_batch_combine`: decontam's own batch-wise identification, so a taxon is scored against the blanks processed alongside it rather than against the pooled cohort. The evidence table gains per-batch calls, because under the default `minimum` rule a contaminant of one run and a contaminant of the kit carry the same verdict and are not the same claim.

- Three input routes: a samplesheet (`--input`), a folder of FASTQ files with automatic mate detection (`--input_dir`), or ENA/SRA accessions downloaded with fastq-dl (`--input_accessions`).
- Accessions are resolved to their run lists before downloading, so an umbrella accession such as a BioProject fans out into parallel per-run downloads. Runs are then grouped back into samples by `--group_runs_by`.
- Host genome handling: use a prebuilt HISAT2 index, a local FASTA, or let the pipeline fetch the assembly from NCBI by accession or taxonomy ID.
- Host depletion with `hisat2 --very-sensitive`, keeping both the aligned reads (sorted, indexed BAM plus samtools statistics) and the unaligned reads (FASTQ).
- Taxonomic classification of the non-host fraction with Kraken2, abundance re-estimation with Bracken, per-sample Krona charts and combined cross-sample tables.
- Alignment QC of the host BAM: samtools stats/flagstat/idxstats plus Qualimap BamQC, both fed into MultiQC.
- Optional AI annotations against any OpenAI-compatible endpoint, ported from [reanalyzerGSE](https://github.com/BioinfoIPBLN/reanalyzerGSE): a narrative of the combined taxonomic profile at the top of the MultiQC report, per-section summaries throughout it, and a summary box in each Qualimap report. Entirely opt-in via `--llm_endpoint`, text-only, strictly serialised, and the endpoint/API key are scrubbed from the published reports.
- A self-contained [shinylive](https://posit-dev.github.io/r-shinylive/) build of the exploreMetaTax Shiny app under `apps/exploreMetaTax/`, for exploring the Kraken2/Bracken tables in a browser with no server. The hosted app at <https://shiny-public.fgcz.uzh.ch/app/exploreMetaTax> remains the faster and more current option.
- Depletion against up to four host references in turn (e.g. GRCh38 then T2T-CHM13, then a blood meal or UniVec): `--host` -- and the superseded `--fasta`, `--hisat2_index`, `--host_accession` and `--host_taxid` -- accept comma-separated lists and can be mixed. A read must fail against every reference to be called non-host, each pass is reported separately in `read_accounting.tsv`, and more references than the pipeline has passes for is refused rather than silently truncated.
- kallisto pseudoalignment as an alternative quantifier wherever the pipeline counts genes: `--host_transcripts` for host expression (from the trimmed reads, independent of depletion) and `--target_transcripts` for the targeted taxon (replacing its genome, index and GTF entirely). Both feed the same DESeq2/edgeR path. Not offered for host depletion, where a transcriptome index would leave intronic and repeat reads to be classified as spurious microbes.
- A targeted-taxon branch (`--target_taxid`): KrakenTools pulls one organism's reads back out of the classification, aligns them to that organism's own genome (`--target_reference`), counts them against its annotation (`--target_gtf`) and tests them with the same `--da_*` contrast. Reuses the host alignment and expression subworkflows rather than duplicating them.
- Host gene expression as an analysis rather than a by-product: `--quantify_host`'s per-sample featureCounts tables are merged into a gene x sample matrix and tested for differential expression (`--host_de_method deseq2,edger`) using the same `--da_*` contrast as the microbial side, plus an optional host-microbe correlation (`--host_microbe_correlation`) that refuses to run when the cohort is too small for any gene x taxon pair to reach significance.
- Optional chunked host alignment (`--hisat2_chunk_size`, `--hisat2_chunk_memory`): the library is aligned in slices, one HISAT2 process each, bounding the memory a single process accumulates and running the slices in parallel. The slices are `-s`/`-u` offsets rather than split files, and the per-chunk BAM, summary and non-host FASTQs are merged back into the files an unchunked run would have produced.
- Per-sample read accounting (`read_accounting/`) with a MultiQC read-fate bargraph, plus a host carry-over metric in the general statistics that audits host depletion using the host genome already present in the Kraken2 database.
- `--bracken_read_length auto`: the trimmed read length is measured per sample from fastp and snapped to a k-mer distribution the Bracken database actually ships, instead of being assumed.
- A sparse-taxon filter on the combined tables (`--min_rel_abundance`, `--min_samples`), with the dropped taxa written out rather than silently discarded.
- Optional HUMAnN 3 functional profiling of the non-host fraction (`--run_humann`), with the taxonomic profile derived from the Kraken2 report via KrakenTools' `kreport2mpa.py` rather than a second classifier, plus regrouping to KEGG orthologs and renormalisation.
- Optional host gene quantification with featureCounts (`--quantify_host`), so host expression and microbial composition come from the same library.
- Optional poly(A) carry-over diagnostic (`--run_polya_check`) comparing internal poly-A/T runs against a length- and composition-matched permutation null.
- `local` and `slurm` execution profiles, with per-process resource tuning and capped, retried downloads.
