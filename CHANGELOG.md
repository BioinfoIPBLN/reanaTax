## v1.0.0dev - [unreleased]

Initial release of BioinfoIPBLN/reanatax, created with the [nf-core](https://nf-co.re/) template.

### `Fixed`

- `--drop_host_taxon` never reached the single-cell matrix. It was an `ext.args` on the abundance filter, so it removed the host from the combined tables and left it in `cell_taxa` -- the one removal in the pipeline that let the two views disagree, against the invariant the rest of the single-cell branch is built on. It showed up as two spurious "significant" Homo sapiens cell-type enrichment results on the CSI-Microbes plate. It now travels on the same shared drop list as every other verdict, so both views agree. Ordering is unchanged where it matters: the matrix is filtered after `--sc_kmer_denoise` and `--sc_ambient`, both of which still see the host rows they need.

- `--single_cell` aligned only the FIRST library of a cohort. `PREPARE_HOST_REFERENCE` emits its STAR index as a queue channel holding one item, and a process pairs a queue channel element-by-element against the reads, so `STARSOLO` ran once and every other library was dropped with no error -- the log said `STARSOLO | 1 of 1` for a three-library run. The bulk route already guards this at every `HISAT2_ALIGN*` call site; this one did not, and had only ever been exercised one sample at a time. Also filtered the null-read tuples that `join(..., remainder: true)` admits, which is how the loss surfaced: as `Path value cannot be null` inside Kraken2, on a process whose own error message then failed to render and reported `No such variable: task` instead.

- `STARSOLO` could not run at all: it forced `--outSAMtype BAM Unsorted` while asking for CB/UB in `--outSAMattributes`, and STAR refuses that combination because the corrected barcode and deduplicated UMI are only known once the solo pass has finished, which it does during the sort. Now `SortedByCoordinate`, with `--limitBAMsortRAM` derived from `task.memory` rather than left at STAR's default of 0 ("the genome index size", ~30 GB for human, on top of the ~30 GB the index already occupies).

- `SCTAXA_FILTER` published every library's filtered matrix under one name. `ext.prefix` was the constant `'reanatax.filtered'`, which is correct on the plate route where `SCTAXA_PLATE` builds a single cohort matrix, but on the droplet route the matrix is per-sample: three tasks wrote `reanatax.filtered.cell_taxa.tsv` into the same publish directory and the last to finish overwrote the rest. Two thirds of the cohort vanished behind a `3 of 3` tick. Now derived from `meta.id`, which leaves the plate filename byte-identical.

- A `--kraken2_db` given as a `.tar.gz` produced a queue channel holding one item, which a process pairs element-by-element against the reads: the cohort would classify its first sample and silently stop. Unpacked-directory databases were unaffected, which is why every benchmark run was correct and the two-sample `test` profile never asserted on it. Now `.first()`, so the database is a value channel available to every task.

### `Added`

- `--drop_host_clade genus|family|order|class|phylum`: drop every taxon under the host's own clade, not just the host taxid. A host read that misses the host genome is assigned to the nearest relative the database holds, so the leakage arrives wearing a sibling's name. Measured on the CSI-Microbes 10x cohort with Homo sapiens already dropped, Pan/Pongo/Gorilla/Macaca/Tupaia were still 84% of everything called microbial in the uninfected library: 0.1% at genus (most databases hold one species per host genus, so that rank is nearly useless), 58-66% at family, 71-88% at class. The lineage is read from the run's own Kraken2 reports, so the ranks match the database and there is no external taxonomy to maintain. It travels on the shared drop list rather than on FILTER_*'s --drop-taxid, so unlike --drop_host_taxon it also reaches the single-cell matrix, where Homo sapiens rows had been outliving it. Off by default and warned at class and above: dropping the host's class is free on human tissue and deletes the mouse on a xenograft. It is a prediction from the taxonomy and not a measurement of the reads, so leakage landing outside the clade -- the same cohort carries turbot, spruce and Naegleria -- still needs --host_kmer_filter.

- `--assembly`: de novo assembly of the non-host fraction, and a verdict on every taxon from the contigs. The five existing filters all score a taxon by counting things about its reads; none of them ever produces a longer sequence, and reads placed by index hopping or piled on one conserved locus do not assemble. MEGAHIT by default rather than an RNA assembler even though the input is usually RNA-seq -- what survives host depletion is overwhelmingly bacterial and archaeal, with no isoform structure to model, and what RNA-seq does impose is coverage skew, which is what a multi-k metagenome assembler is for; `--assembly_assembler metaspades` trades time and memory for contiguity. Libraries are POOLED first (`--assembly_pool group|all|sample`, defaulting to the contrast groups): per-library assembly is close to useless on the cohorts this is for, where a false positive sits at tens of reads per library. Contigs roll up the taxonomy from the contig report's own indentation, so a species-level contig supports the genus above it -- which is the rank where every false positive on the CSI-Microbes plate lived. Evidence only by default: `--contig_filter` is opt-in because a contig is strong positive evidence while its absence is weak negative evidence, and `--contig_min_reads` records rather than condemns a taxon too rare to have assembled.

- `--export_biom`: the classification as a BIOM table in `biom/`, off by default and read by nothing in this pipeline. The combined tables are already a taxa-by-sample matrix, which is why the differential-abundance step skips the `kraken-biom` round trip `EzAppDiffShot` does; this is for handing a run to QIIME 2, phyloseq or anything else that speaks BIOM. Built from the same per-sample reports Krona uses, then restricted to the taxids in the filtered combined report so it agrees with `*_filtered.tsv` instead of quietly reinstating everything the filters removed -- the pre-filter table is published as `*.unfiltered.biom` when the two differ. `--biom_metadata` (falling back to `--da_metadata`) is attached as sample metadata, and a sample missing from it stops the export by name rather than inside `pandas`. Two of kraken-biom's own behaviours are corrected on the way in: it names samples after the report FILE, so the reports are re-linked under their sample ids first; and it parses reports with a fixed six-field reader, so the two extra columns from `--kraken2_report_minimizer_data` are dropped rather than silently shifting rank, taxid and name. Ranks run domain to species rather than kraken-biom's default of order to species, because on the CSI-Microbes plate every false positive the control filter removed sat at genus.

- `--compression_level`, `--alignment_output_format` and `--cleanup_intermediates`: three independent answers to how much disk a reanalysis run holds. One 180-well cohort left 1.2 TB in `work/` -- 496 GB of alignments, 413 GB of FASTQ. The level reaches `samtools sort -l`, `samtools view -l`, `samtools fastq -c`, `fastp -z` (clamped to 1, which fastp requires) and the `pigz`/`gzip` calls in the local modules. `cram` roughly halves the sorted host alignments, indexes the reference once per pass rather than letting htslib rebuild it inside every task, and is refused up front alongside Qualimap and `--quantify_host` rather than failing per sample at the end of a run. `--cleanup_intermediates` deletes the per-chunk BAMs from inside the merge task once `samtools cat` has returned, and the downloaded FASTQs once trimming and raw FastQC have both read them -- ordering enforced by taking those tasks' outputs as inputs. Only paths inside the work directory are ever removed, so a samplesheet's own FASTQs are skipped and recorded rather than deleted; off by default, because a deleted intermediate cannot be resumed.
- `--negative_controls` / `--prevalence_filter`: the first filter here whose verdict is per LIBRARY rather than per taxon, and the only one that speaks to index hopping or well-to-well carryover. Those put genuine reads of a genuine organism into the wrong library -- nothing about the reads is wrong, so no evidence filter can see them, and the same taxon is then signal in one library and carryover in the next, which no single verdict per taxon can express. Measured on the CSI-Microbes plate, the distinct-minimizers-per-read ratio recommended by Kraken2's manual ranks those false positives ABOVE the true positives (AUC 0.415), and `--decontam`'s prevalence method must either delete the spiked organism or spare it entirely. A taxon is kept in a library only where it exceeds a stated multiple of its level in the controls, in counts per million classified reads; failing cells are zeroed and taxa failing everywhere leave as taxids. `--control_floor_reads` treats absence from the blanks as the bound it is rather than as zero, without which the test collapses to "any reads at all" for every taxon the controls missed. On the CSI-Microbes plate this is what turns the scorecard from 1 FAIL / 3 PASS into 0 FAIL / 4 PASS (specificity 88.2% -> 97.1%), at a cost of 4 of 62 detections. `sc_enrichment` is given the control list and leaves those libraries out of the test entirely: after the filter runs they are the only libraries still carrying their full background, so treating them as a cell type makes every reagent contaminant look hugely enriched in the blanks -- on that plate, 41 of 43 significant results, at log2fc 3.9 and adjusted p of 0. `--sc_apply_drop_list` carries the per-library verdicts into the cell-by-taxon matrix as well, taken from the combined kreport rather than from Bracken: the matrix holds whatever rank Kraken2 assigned, every false positive there sat at genus rather than species, and Bracken-derived verdicts reached none of them. `--prevalence_filter` is the no-controls fallback -- on that plate it removes six taxa holding 62.6% of all microbial reads, every one a known reagent contaminant, without touching the spike, and leaves the specificity failure exactly where it was, because the spiked organism is itself in 101 of the 180 libraries -- and is off by default because it is only sound where a universally present taxon cannot be real.
- `--sc_ambient`: how strongly each taxon is associated with cells rather than with the ambient pool, from STARsolo's raw and filtered matrices. Deliberately an annotation and not a filter: an empty droplet holds reagent contaminants, ambient soup, microbes from lysed cells AND genuine extracellular organisms from the tissue, so a taxon as common in the medium as in the cells is reported as `ambient_undecided` rather than as contamination -- only `--decontam`'s blanks settle that. `--sc_ambient_drop` will remove them, and is documented as correct only when the question is about intracellular microbes.
- `--prism_barcode_only`: drops the barcode read before PRISM sees the library, so Kraken2, STAR, minimap2 and BLAST all work on the cDNA read alone. Stricter than PRISM's own `--barcode_only`, which reaches only its BLAST step. Required with `--single_cell`, which is otherwise refused.
- `--univec`: UniVec depletion as a pass of its own, with its own alignment stringency. Not another `--host` entry, because `--very-sensitive` (`--score-min L,0,-1`) against a 3 kb plasmid backbone removes real reads; this pass runs end-to-end at HISAT2's own threshold and does not inherit `--hisat2_args`. Runs last, publishes the non-host FASTQs, appears in `read_accounting.tsv`, and works with `--skip_host_removal`.
- `--run_prism`: PRISM (sjdlabgroup/PRISM) wrapped as its authors wrote it -- candidate taxa confirmed by full-length BLAST against `nt`, GenBank annotation, host mapping and k-mer composition, scored by its XGBoost model over forty features. Takes the trimmed reads rather than the non-host ones, because several of its features are statistics of its own host removal. No public container exists, so `--prism_container` is required under docker/singularity and the module ships a conda environment for the alternative.
- `--shuffle_control`: a shuffled-read negative control. Every library is classified twice -- once as sequenced, once with each read shuffled so that its length, GC content and dinucleotide frequencies survive and none of its k-mers do -- and the ratio between the two is what the database produces from base composition alone. Three shuffles (`dinuc`, the Altschul-Erickson Euler-path shuffle, is the default), a fixed seed, an enforced detection floor when subsampling, and a second Kraken2 pass run with identical arguments to the first.
- `--gene_diversity_filter`: PRISM's `gene_div`, `prod_div`, `fprod`, `fugene` and `fuprod`, reproduced under PRISM's own names and definitions from HUMAnN's species-stratified gene-family table -- raw Shannon entropy as `vegan::diversity()` returns it, and shares of the across-taxa total rather than raw counts. A taxon's reads either spread across many gene families or pile onto one locus, and no read count can tell the difference. Runs a second time on the regrouped table when `--humann_regroup` is set, which separates "many gene families" from "many products". PRISM's score itself needs the other thirty-five features and is not reproduced; use `--run_prism` for that.
- `--pathseq_microbe_bwa_image`: GATK PathSeq as a third classification route, and the only one here that aligns rather than matching k-mers. Reports `unambiguous` reads separately from shared ones, and its results are kept in PathSeq's own units rather than converted into a Kraken report, so a disagreement between the routes stays visible.
- `--run_sparcc`: taxon co-occurrence inferred with SparCC (FastSpar). Refuses to start when the cohort cannot support the network -- fewer than ten samples, or a bootstrap p-value floor above what Benjamini-Hochberg needs for the number of pairs -- because an empty network from such a run means "this cohort cannot be asked" rather than "there are no associations".
- `--sc_host_de`: the host half of SAHMI. Host expression compared between cells carrying a taxon and bystander cells of the same type, by Wilcoxon rank-sum on log-normalised counts (Seurat's `FindMarkers` defaults). Requires cell-type annotations, because which cell types carry a taxon is itself a result and a pooled test would report the difference between cell types as a response to infection.
- `--sc_plate_based`: CSI-Microbes' plate-based route, for Smart-seq2 and relatives where every well is its own library. No barcode and no STARsolo -- each cell runs the bulk route and the cell-by-taxon matrix is those per-cell reports stacked -- and everything downstream of the matrix is shared with the droplet route.
- `--decontam_batch_column` and `--decontam_batch_combine`: decontam's own batch-wise identification, so a taxon is scored against the blanks processed alongside it rather than against the pooled cohort. The evidence table gains per-batch calls, because under the default `minimum` rule a contaminant of one run and a contaminant of the kit carry the same verdict and are not the same claim.

- Three input routes: a samplesheet (`--input`), a folder of FASTQ files with automatic mate detection (`--input_dir`), or ENA/SRA accessions downloaded with fastq-dl (`--input_accessions`).
- Accessions are resolved to their run lists before downloading, so an umbrella accession such as a BioProject fans out into parallel per-run downloads. Runs are then grouped back into samples by `--group_runs_by`.
- Host genome handling: use a prebuilt HISAT2 index, a local FASTA, or let the pipeline fetch the assembly from NCBI by accession or taxonomy ID.
- Host depletion with `hisat2 --very-sensitive`, keeping both the aligned reads (sorted, indexed BAM plus samtools statistics) and the unaligned reads (FASTQ).
- Taxonomic classification of the non-host fraction with Kraken2, abundance re-estimation with Bracken, per-sample Krona charts and combined cross-sample tables.
- Alignment QC of the host BAM: samtools stats/flagstat/idxstats plus Qualimap BamQC, both fed into MultiQC.
- Optional AI annotations against any OpenAI-compatible endpoint, ported from [reanalyzerGSE](https://github.com/BioinfoIPBLN/reanalyzerGSE): a narrative of the combined taxonomic profile at the top of the MultiQC report, per-section summaries throughout it, and a summary box in each Qualimap report. Entirely opt-in via `--llm_endpoint`, text-only, strictly serialised, and the endpoint/API key are scrubbed from the published reports.
- A self-contained [shinylive](https://posit-dev.github.io/r-shinylive/) build of the exploreMetaTax Shiny app under `apps/exploreMetaTax/`, for exploring the Kraken2/Bracken tables in a browser with no server. The hosted app at <https://shiny-public.fgcz.uzh.ch/app/exploreMetaTax> remains the faster and more current option.
- Depletion against up to four host references in turn (e.g. GRCh38 then T2T-CHM13, then a blood meal or UniVec): `--host` -- and the superseded `--fasta`, `--hisat2_index`, `--host_accession` and `--host_taxid` -- accept comma-separated lists and can be mixed. A read must fail against every reference to be called non-host, each pass is reported separately in `read_accounting.tsv`, and more references than the pipeline has passes for is refused rather than silently truncated.
- kallisto pseudoalignment as an alternative quantifier wherever the pipeline counts genes: `--host_transcripts` for host expression (from the trimmed reads, independent of depletion) and `--target_transcripts` for the targeted taxon (replacing its genome, index and GTF entirely). Both feed the same DESeq2/edgeR path. Not offered for host depletion, where a transcriptome index would leave intronic and repeat reads to be classified as spurious microbes.
- A targeted-taxon branch (`--target_taxid`): KrakenTools pulls one organism's reads back out of the classification, aligns them to that organism's own genome (`--target_reference`), counts them against its annotation (`--target_gtf`) and tests them with the same `--da_*` contrast. Reuses the host alignment and expression subworkflows rather than duplicating them.
- Host gene expression as an analysis rather than a by-product: `--quantify_host`'s per-sample featureCounts tables are merged into a gene x sample matrix and tested for differential expression (`--host_de_method deseq2,edger`) using the same `--da_*` contrast as the microbial side, plus an optional host-microbe correlation (`--host_microbe_correlation`) that refuses to run when the cohort is too small for any gene x taxon pair to reach significance.
- Optional chunked host alignment (`--hisat2_chunk_size`, `--hisat2_chunk_memory`): the library is aligned in slices, one HISAT2 process each, bounding the memory a single process accumulates and running the slices in parallel. The slices are `-s`/`-u` offsets rather than split files, and the per-chunk BAM, summary and non-host FASTQs are merged back into the files an unchunked run would have produced.
- Per-sample read accounting (`read_accounting/`) with a MultiQC read-fate bargraph, plus a host carry-over metric in the general statistics that audits host depletion using the host genome already present in the Kraken2 database.
- `--bracken_read_length auto`: the trimmed read length is measured per sample from fastp and snapped to a k-mer distribution the Bracken database actually ships, instead of being assumed.
- A sparse-taxon filter on the combined tables (`--min_rel_abundance`, `--min_samples`), with the dropped taxa written out rather than silently discarded.
- Optional HUMAnN 3 functional profiling of the non-host fraction (`--run_humann`), with the taxonomic profile derived from the Kraken2 report via KrakenTools' `kreport2mpa.py` rather than a second classifier, plus regrouping to KEGG orthologs and renormalisation.
- Optional host gene quantification with featureCounts (`--quantify_host`), so host expression and microbial composition come from the same library.
- Optional poly(A) carry-over diagnostic (`--run_polya_check`) comparing internal poly-A/T runs against a length- and composition-matched permutation null.
- `local` and `slurm` execution profiles, with per-process resource tuning and capped, retried downloads.

### `Fixed`

- Corrected the documented effect of `--very-sensitive`: `-k 50` costs alignment time, not disk. The HISAT2 module pipes through `samtools view -F 256`, so secondary alignments never reach the BAM — which is also why the BAM can be counted directly with featureCounts.
- `hasClassifiedReads` no longer uses a `while` loop, which `nextflow lint` rejects.
